## Task 06B

**Train one elastic model whose representations survive several deployment envelopes — VERDICT: cut.**

Current raw formula: `S = (1/3) Σ_v (0.85 a_v + 0.15 e_v), with three nested configurations and shared-size caps.` See [06B §Reward](/workspace/task_design_v2_codex/06_architecture_resource_codesign.md:259). All table payouts are estimates using F above; actual anchors and attainable outcomes are to verify.

### Audit of the task’s own saturation section and kill criteria

Its own section explicitly calls standard elastic training potentially fatal and requires a shared attainable frontier. Neither exists as evidence. Envelope count can increase ordinary multiobjective tuning without adding dependency depth, while independent-model perfection says nothing about a shared optimum. The correct first action is a cheap named nested-transformer baseline and sharing audit, not the full S1–S4 campaign. Source: [06B §Saturation resistance](/workspace/task_design_v2_codex/06_architecture_resource_codesign.md:281); experiments: [06B §E2/E3](/workspace/task_design_v2_codex/06_architecture_resource_codesign.md:322). The common protocol critique above also applies.

### Verdict justification

Cut this standalone candidate from the initial portfolio and keep it as a later 06A/architecture variant only if physical anchors justify re-entry. Existing elastic transformer methods address the central task directly, the permitted shared parameterization is not specified enough to exclude partitioned models, and the achievable shared frontier is unknown. This recommendation follows the packet’s own early-kill posture; it is not a fabricated empirical failure.
