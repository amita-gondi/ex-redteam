## Task 04A

**Recover useful asynchronous MoE learning across version, routing and cache boundaries — VERDICT: needs fixes.**

Current raw formula: `S = 0.75 a + 0.25 e, with e valid-update throughput divided by an optimistic bound.` See [04A §Reward](/workspace/task_design_v2_codex/04_training_fidelity.md:127). All table payouts are estimates using F above; actual anchors and attainable outcomes are to verify.

### Audit of the task’s own saturation section and kill criteria

The own-section fallback warning is credible and should be the first cheap kill test. Its stated two-chain requirement is stronger than the generic graph actually demonstrates: A→C→D is one treatment branch, while B→D joins it. Increasing version-domain count can still be handled by one universal protocol. The formal perfect-quality/roofline corner is not a feasible joint optimum. Require the healthy-stack frontier and probe indistinguishability before the shared maximum and best-of-k campaign. Source: [04A §Saturation resistance](/workspace/task_design_v2_codex/04_training_fidelity.md:149); experiments: [04A §E2/E3](/workspace/task_design_v2_codex/04_training_fidelity.md:190). The common protocol critique above also applies.

### Verdict justification

This is one of the more defensible candidates because asynchronous fidelity is a real systems problem with end-to-end learning consequences. It still needs evidence that an optimized healthy fallback or composed standard correction does not solve it, a fixed definition of useful updates, and tests against code that behaves correctly only on semantic probes. The current quality/rate weights can make the required physical margin impossible without additional capability gain.
