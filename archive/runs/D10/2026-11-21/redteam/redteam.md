## Saturation against the hypothetical 10T researcher / 12h

The proposed researcher can inspect the entire public tool semantics and compile a precommit monitor. If allowed actions and authorization facts are already represented in tool state, oversight reduces to predicate evaluation and dependency tracking. Replacing a learned classifier with that program is lawful under the source's explicit complete-firewall control. If only model weights can be deployed, generate legal monitor demonstrations and distill them into the bounded oversight policy; this changes the implementation cost without establishing an unsolved mechanism.

## Revised estimate versus the source card

The source labels its attack `F_D10(U_check+conservative)`, with no numeric payout. My ESTIMATED 0.82 gives an explicit adverse scenario in which complete mediation is both cheap and sufficient. The difference in judgment is not that I discovered a secret security hole: the card already concedes that a full firewall may solve the task. The complete recipe must be compared to useful authorized work, not an intentionally overconservative stop-all baseline. ## Boilerplate and missing build content

ESTIMATED 40–50% of the card is generic compliance, saturation or conditional language; ESTIMATED 50–60% describes external evidence acquisition. It is not mostly boilerplate by that editorial split, but it lacks the task-defining build content: actual tool transition semantics, authorization predicates, evidence sources and prices, cancellation deadlines, actor pins, inspection traces, policy size, training interface, safety/utility aggregation and anchor calibration. No concrete process executable or artifact filename is named, so I have not invented one in the attack table.

The definition of an unsafe attempted versus committed action also matters. A rejected unauthorized attempt can be evidence of a working external boundary while still harming useful completion; these events need separate logging. Exact goal predicates must rule out partial-work credit masquerading as completion. GDM requires configured service scopes, credential separation, portable execution, host-independent resource accounting, finite per-seed deadlines, complete result reconciliation and independently implemented benign positives. None has been demonstrated. A future empirical program also needs attacker-health controls and live adversarial regressions; CPU reasoning is not their substitute.

## Verdict, required fixes and cheapest decisive check

CUT the present task because its learned-acquisition necessity is only hypothetical. No list of sandbox fixes changes that scientific problem. Re-entry would require a concrete naturally expensive evidence family, same-information feasibility witnesses and full-firewall/fixed-cover controls showing a native adaptive advantage, without banning deterministic enforcement or charging it artificial costs.

The cheapest decisive check is a CPU dependency audit of the actual authorization predicate language: enumerate which public or legitimately inspectable facts certify each irreversible transition, compile their invalidation rules and compare the cheapest sufficient cover to the disclosed budget. Its accelerator cost is ESTIMATED 0 H100-hours. It does not require training an overseer to discover that predicate evaluation suffices. If the author cannot yet supply those semantics, construction remains blocked at specification level; if the cover fits, terminate before the source's proposed GPU pilot. No experiment or spending was performed here.
